# Show workflow status on the map — Design

Status: Approved
Approval: Approved by @Dead0utside on 2026-11-13, including the decision that a feature with an unknown workflow status is not drawn in the "Workflow Status" mode
Requirements: ./requirements.md

## Scope revision (requested by @Dead0utside after implementing T-01 to T-06)

The implementation was reduced after the user judged it too large for the feature. Not yet reflected in `requirements.md` (pending the user's decision, see R-05, R-05a):

- **Live update:** only the editor effect, `appSharedStateActions.updateAssetWorkflow`, and the `asset-search` reducer patch of `geometries` remain. This is the same freshness as "Freigabe": the overview repaints through the existing `selectGeometries` → `setGeometries` path. The filtered results and the open asset are **not** repainted in place; they show the new status after the next search or when the asset is opened again. Removed: `MapController.updateAssetWorkflow`, `findWorkflowOnlyChanges`, the `map.component.ts` wiring, the `app-shared.reducer.ts` patch and the `results.data` patch (patching them would make `setAssets` / `setActiveAsset` re-zoom).
- **Not-yet-reindexed documents:** no special handling. `workflowStatus` is non-nullable everywhere, `readSearchResultItem`, the `status` source field, the tolerant CSV parsing and the "draw nothing for an unknown status" rule are removed. Until the deployment re-index ran, such documents lack the fields and are not colored correctly.
- **Other extras removed:** the `map-colors.ts` refactor of the "Geometrie" and "Freigabe" styles (the new style defines its five colors itself), the `asset-viewer` Jest `transformIgnorePatterns` change, and the heavy specs (`map-controller.spec.ts`, `map-layer-translations.spec.ts`, `workflow-based.map-layer-style.spec.ts`, `app-shared.reducer.spec.ts`, `asset-search.utils.spec.ts`, `file-search.service.spec.ts`).

The task list and results below describe T-01 to T-06 as originally designed; this section takes precedence where they differ.

## Existing implementation

Map styling (`libs/asset-viewer`):

- `shared/map-configuration/map-layer-styles.ts` defines `LayerStyleIdentification = 'geometry' | 'access'`, `availableLayerStyles` (each entry: `name`, `styleFunction`, `styleItems[{translationKey, iconKey, generalizedIconKey?}]`) and `defaultLayerStyle = 'geometry'`.
- `styles/geometry-based.map-layer-style.ts` and `styles/access-based.map-layer-style.ts` return a `LayerStyle<T>` (`point.{pointInstance,lineInstance,polygonInstance}`, `line`, `polygon`) and read the feature property `CustomFeatureProperties.GeometryType` / `AccessType` (`styles/custom-feature-properties.enum.ts`).
- `components/map-legend/map-legend.component.*` cycles through `Object.keys(availableLayerStyles)` in `handleChange()` and renders `styleItems` with `<svg-icon [key]>`. Adding a style key therefore adds the mode and its legend automatically; the title is `mapLayers.<name>.name` and the labels are `translationKey`s.
- Icon keys are registered in `libs/client-shared/src/lib/icons/map-styles/{access,geometry}.ts` and `icons/index.ts`.
- `components/map/map-controller.ts` creates features and sets their properties in three places: `setGeometries` (overview, from `/api/geometries`, layer `assetLocations`), `setAssets` (filtered view, layer `assetGeometries`; zooms to the results) and `setActiveAsset` (reuses an existing `assetGeometries` feature or creates one). `handleStyleChange` swaps the style function on the layers. `map.component.ts` feeds it from the store (`selectSearchResults`, `selectCurrentAssetAndGeometries`, `selectGeometries`).

Data flow of the workflow status:

- `POST /api/geometries` (`apps/server-asset-sg/src/features/geometries/geometries.controller.ts`) runs an unpaged Elasticsearch search, maps hits (`AssetSearchResultItem`) with `mapToGeometry` and streams one CSV line per geometry (`serializeGeometryAsCsv`: `id;assetId;;accessType;x;y`). `GeometryService.fetchAll` parses these lines.
- The search result `data` blob (`AssetSearchResultItem`, no workflow info) is built in three places: `asset-search-writer.service.ts` (`mapAssetToElastic`), and `file-search-writer.service.ts` (`writeAssetFiles` path and the batch path that has its own Prisma query). It is decoded in `asset-search.service.ts` and `file-search.service.ts` via `AssetSearchResultItemSchema`.
- The Elasticsearch document already has the top-level field `status`, but `hasRequestedChanges` is not indexed anywhere.
- `Asset.workflowStatus` is loaded in `prisma-asset.ts` (`assetSelection.workflow.select = { status: true }`, fallback `'Draft'`). `has_requested_changes` is a column of the `workflow` table (`Workflow.hasRequestedChanges` in Prisma, default `false`).
- The only write path of workflow data in the server is `WorkflowRepo.change` via `WorkflowService` (`addChange`, `publish`), which already ends in `registerAssetForChange` → `SearchWriterService.register`. `register` reloads the asset through `assetRepo.find` and thus through `assetSelection`. `fixtures-create.command.ts` creates workflows (with `hasRequestedChanges: false`) and indexes via the same writers.
- Client state: after an asset update, `asset-search.reducer.ts` handles `appSharedStateActions.updateAsset` by rebuilding `state.geometries` (with `accessType` from `asset.isPublic`); it does not touch `results.data`. The asset editor loads the workflow with `loadWorkflow$` and dispatches `setWorkflow({ workflow })` (also from `asset-editor-status.component.ts` after each workflow action). `Workflow` carries `id` (= asset id), `status` and `hasRequestedChanges`.

## Approach

1. **One derived map category.** A pure helper `mapAssetWorkflowToMapStatus({ workflowStatus, hasRequestedChanges })` (next to `utils/access-type.ts`) returns `WorkflowStatus | 'RequestedChanges' | null` per R-03 (`null` input status → `null`; Published always Published; Draft/InReview/Reviewed with the flag → `RequestedChanges`; otherwise the status). The controller stores only this category in a single new feature property `CustomFeatureProperties.WorkflowStatus` (not set when `null`); the style function only reads that property.
2. **New layer style `workflowStatus`** (`styles/workflow-based.map-layer-style.ts`), modeled on `access-based.map-layer-style.ts`. Shapes, widths, transparency and z-index are reused from `style-constants`/`utils`. Colors reuse the existing fill/stroke pairs (InReview from Geometrie polygon, Reviewed from Geometrie point, Published from Freigabe public, Requested changes from Freigabe internal); only Draft is new (`rgb(172,180,189)` / stroke `#131b22`). The existing colors are extracted into shared constants if they are not already exported, so both modes use one definition (R-02). Registered as key `workflowStatus` after `access`, so the cycle order is Geometrie → Freigabe → Workflow Status (R-01); the default stays `geometry`.
3. **Legend.** Five `styleItems` in the order Draft, InReview, Reviewed, Published, RequestedChanges with `translationKey`s `workflowStatus.<Status>` and `mapLayers.workflowStatus.items.requestedChanges`; the title is `mapLayers.workflowStatus.name`. Published and Requested changes reuse the existing square swatches `access-public` and `access-locked`. New square swatches `status-draft`, `status-in-review` and `status-reviewed` are added in `icons/map-styles/status.ts` in the format of `access.ts`, using the colors above. No change to the legend component.
4. **Data contract.** Because `Geometry` is also embedded in `Asset.geometries`, it is not changed. Instead a new `MapGeometry extends Geometry { workflowStatus: WorkflowStatus | null; hasRequestedChanges: boolean }` is used wherever the overview geometries are produced or consumed (controller, CSV, `GeometryService`, search state). `AssetSearchResultItem` and `AssetSearchResultItemSchema` get the same two fields (`workflowStatus: WorkflowStatus | null`). `null` means "unknown": it is never written by the index writers and only occurs for data that predates this feature (see step 6). `Asset` (database-backed) gets a non-null `hasRequestedChanges: boolean` next to its non-null `workflowStatus`, so the writers fill both from the already loaded asset.
5. **CSV.** Two columns are appended: `id;assetId;;accessType;x;y;workflowStatus;hasRequestedChanges`. `workflowStatus` is the enum value or empty when `null`; `hasRequestedChanges` is `1`/`0`. The line stays streamable and the payload grows by about 10 bytes per geometry (R-06). An old client ignores the extra columns because its parse destructures only the first six.
6. **Documents that have not been reindexed yet.** The index writers always write both fields, `register()` reindexes on every workflow write (R-05), and the reload goes through `assetSelection`, so adding `hasRequestedChanges` there is sufficient. Documents indexed before the deployment (and before its re-index finishes) have a `data` blob without the two fields. Each layer handles this explicitly, so nothing throws and no color is invented:

   | Layer                                                                                                                                                                                                                                                                                 | Input                                                                            | Result                                                                                                                                                                                                                                                   |
   | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | Search decoding (`readSearchResultItem`, one shared function used by `asset-search.service.ts` and `file-search.service.ts`; runs on the raw JSON **before** the `decode` branch, so `decode: false`, used by `/api/geometries`, is covered too; `status` is added to `sourceFields`) | `data` has the fields                                                            | used as is                                                                                                                                                                                                                                               |
   |                                                                                                                                                                                                                                                                                       | `data.workflowStatus` missing, top-level ES `status` is a valid `WorkflowStatus` | `workflowStatus` = ES `status` (the index already holds it today)                                                                                                                                                                                        |
   |                                                                                                                                                                                                                                                                                       | `data.workflowStatus` missing and `status` missing/invalid                       | `workflowStatus` = `null` (no Draft fallback)                                                                                                                                                                                                            |
   |                                                                                                                                                                                                                                                                                       | `data.hasRequestedChanges` missing                                               | `false` (the flag was never indexed, so it is unknowable)                                                                                                                                                                                                |
   | CSV serialization (`serializeGeometryAsCsv`)                                                                                                                                                                                                                                          | `workflowStatus` is `null`                                                       | empty status column, line otherwise valid                                                                                                                                                                                                                |
   | Client parsing (`GeometryService`)                                                                                                                                                                                                                                                    | status column missing (old server), empty, or not a `WorkflowStatus` value       | `workflowStatus` = `null`                                                                                                                                                                                                                                |
   |                                                                                                                                                                                                                                                                                       | flag column missing or not `1`                                                   | `hasRequestedChanges` = `false`                                                                                                                                                                                                                          |
   | Map (`mapAssetWorkflowToMapStatus`, controller, style)                                                                                                                                                                                                                                | `workflowStatus` is `null`                                                       | helper returns `null`; the controller does not set `CustomFeatureProperties.WorkflowStatus`; the workflow style function returns no style for such a feature, so it is not drawn in the "Workflow Status" mode only. The other modes ignore the property |

   Consequence, accepted until the re-index: a not-yet-reindexed asset that has requested changes is shown with its status color instead of the Requested-changes color. Its status is correct because it comes from the existing ES `status` field. Reindexing an asset (a workflow change, or the deployment re-index) replaces the document and removes the gap.

7. **Repaint on status change without re-zoom and without swallowing other updates (R-05a).** The store is the single source of truth and the map derives its in-place updates from state changes, never from a separate side channel:
   - A new shared action `appSharedStateActions.updateAssetWorkflow({ assetId, workflowStatus, hasRequestedChanges })` is dispatched by an asset-editor effect on `setWorkflow` (using `workflow.id`, `status`, `hasRequestedChanges`).
   - Reducers patch only the two workflow fields and keep every other field and reference: `asset-search.reducer.ts` patches the matching entries of `state.geometries` (`{ ...geometry, workflowStatus, hasRequestedChanges }`, so `accessType` is kept) and of `state.results.data` (`{ ...item, workflowStatus, hasRequestedChanges }`, so `isPublic` and the `geometries` array are kept); `app-shared.reducer.ts` patches `currentAsset.asset` the same way and keeps `currentAsset.geometries`. Each returns the same state reference when the values are already equal, so opening an asset (which also dispatches `setWorkflow`) causes no map work.
   - Overview: the patched `state.geometries` flows through the existing `selectGeometries` → `setGeometries` path, which rebuilds the `assetLocations` features without zooming. This is the same path through which `accessType` updates reach the overview today, and it keeps `accessType`.
   - Filtered view and active asset: re-running `setAssets` or `setActiveAsset` would re-zoom, and a comparator that only looks at ids would swallow real changes such as `isPublic`. Instead `map.component.ts` compares the previous and next value of each of the two subscriptions (`selectSearchResults`, `selectCurrentAssetAndGeometries`) with a pure helper `isWorkflowOnlyChange(previous, next)` for items: same key set, and every key except `workflowStatus` and `hasRequestedChanges` equal by reference (`Object.is`). For the results list all items must be identical or workflow-only and at least one differs; for the current asset the `geometries` reference must also be identical. If this holds, the component calls `controller.updateAssetWorkflow(item)` for each changed item and skips `setAssets` / `setActiveAsset`. In every other case (first emission, new search, different order, changed `isPublic` or any other field, or a status change combined with such a change) the existing path runs unchanged, including its zoom and its AccessType update. The reference comparison is deliberately conservative: any doubt falls back to today's behavior, so a Freigabe change can never be skipped.
   - `MapController.updateAssetWorkflow(item)` computes the category and sets only `CustomFeatureProperties.WorkflowStatus` on the existing features of that asset in the `assetGeometries` and `activeAsset` sources (looked up by the geometry ids of the item), and replaces the item in `assetsById` and `activeAsset`. It does not clear a source, touch `AccessType`, call `zoomToGeometries` or change the view. Setting a property fires the feature change event, so the layers repaint. The selection/hover buffer features use fixed interaction styles and are unaffected.
   - `updateAsset` (after a save) keeps working as today and additionally fills the two workflow fields of the rebuilt `state.geometries` from the saved asset; the `loadWorkflow` that follows every save dispatches `setWorkflow` and so corrects them if the saved asset carried an outdated status.

## Risks and open questions

- **Stale index until the deployment re-index** (accepted in requirements): handled by the fallback table in Approach step 6. Decision to confirm: for an asset without any status information (should not occur, since the index already holds `status`), the workflow mode draws nothing instead of using a fallback color, in line with "remove the Draft fallback". For not-yet-reindexed assets the requested-changes override cannot be shown until reindexing, because the flag was never indexed.
- **Re-zoom and swallowed updates.** The design avoids both by comparing state values (`isWorkflowOnlyChange`) instead of ids, and by taking the in-place path only when nothing but the two workflow fields changed. The remaining risk is a missed in-place case, which only costs a re-zoom as today, never a missed color. A pending `setActiveAsset` (it runs in a `setTimeout`) that was captured before a workflow update could still apply the older status; it is corrected by the next state change and by the `setWorkflow` that follows every load and save.
- **Swatch icons.** The three new icons are drawn from the specified colors and need visual comparison with the mockups; no design asset exists beyond the screenshots.
- **Payload.** `/api/geometries` grows by two short columns per line (R-06); to be checked against the current response size.
- **Flag semantics.** `hasRequestedChanges` is stored as-is and is not reset on status change; the map follows R-03 regardless of how the server sets it.
- **Elasticsearch/DB for tests.** Server integration tests require the test docker-compose to be running.

No open questions block implementation; the "draw nothing when the status is unknown" decision above is the one to confirm.
